# Brief: the Explorer section and the shared filter panel

You are building the **Explorer** (`#/explorer`, Spanish label "Explorador") of "Bets Tracker", a read-only PWA over Juan's soccer betting Google Sheet, and the **shared filter panel** that the Simulator and Analysis sections will reuse right after you. Juan's words: he wants to "filter them by market, by price ranges (<=2.0, <2.0, <=2.5, etc), by everything that can be filtered (VALOR, VALOR CASI, TARJETAS UNDER, SHADOW, etc), by slate run dates". He opened the placeholder today and asked where the filters are, so this is the most awaited part.

## What to build

1. **Shared filter panel** in `src/lib/ui/filter-panel.js` (exported from `src/lib/ui/index.js`), with its CSS in `src/styles/components.css` (or a new `src/styles/filter-panel.css` linked from `index.html`) and its strings under the shared `filters.*` keys in `src/i18n/*.json`. It is a controlled component over the filter state of `src/data/filters.js`: `<FilterPanel picks=… filters=… onChange=… hide=[…] />` plus `<ActiveFilters filters=… onChange=… />` (removable chips of what is active, with "clear all") and `<FilterButton count=… onClick=… />`. On phones it opens as a bottom sheet with a sticky "show N picks" button and a live count; on wide screens it is a side column. Every field in the filter state must be reachable: source; tag (multi, with counts, sheet labels, grouped: price-first tests, model tests, published, filter rejects…); market family and raw market; league (searchable, there are dozens); book; status; price presets as chips (every preset in `PRICE_PRESETS`, including ≤2.0, <2.0, ≤2.5) and custom min/max; date presets (last slate, 7 days, 30 days, this month, since a date), a from/to range and a single slate date picker; has closing price; has two-sided close; reference; sample; FUERZA; filter reason; EV range; model probability range; free text. Options with zero matches under the other active filters are shown disabled or hidden, with counts. Sections collapse; the most used (source, tag, price, date, market, status) come first. Document the component in `docs/FEATURE_GUIDE.md` (a short "Filter panel" subsection with a usage example) so the next agents can drop it in.
2. **Saved filters**: save the current combination with a name, list, apply, delete (uses `savePreset`/`deletePreset` in `settings.js`; Settings already lists them). Offer a few built-in starting points (for example "VALOR ≤ 2.0", "Tarjetas under", "Córners equipo 10+") that only fill the panel.
3. **Explorer screen**: the filtered list (cards on phones, a real table on wide screens with sortable columns: date, match, tag, market, selection, price, close, EV, fair-close EV, status), sort control, search, paging, URL-synced state (every filter lives in the hash query so a view can be bookmarked and shared).
4. **Summary strip for the current filter** above the list: record, hit rate vs break-even, flat yield at 1u, units, mean fair-close EV ± 2 SE with n, pending count, one written sentence (use `summaries.js`), and a small cumulative sparkline. This is how Juan answers "how are the VALOR CASI picks priced ≤2.0 doing?" without leaving the page. Add a button "Simular estos picks" that opens `#/simulator` with the same query string.
5. **Pick detail** (`#/explorer/:uid`, sheet on phones): everything about the pick in readable form: source and sheet row ("Sombra fila 412"), tag with its meaning in one line, market, selection, price, books and each book's price, closing price and the other side, CLV and fair-close EV with a one-line explanation, model / blend / fair / AI probabilities, EV, fair odds, reference, sample, FUERZA, feed price and opening, Pinnacle 1X2 open → last (join `data.pinnacle` by `parsed.pin.id` when present), status and result text, and the raw notes at the end. Previous / next within the current filtered list.
6. Tests: unit tests for any data-layer addition; e2e for filtering by tag, price preset, date preset, combined filters, URL round-trip (reload keeps the view), saved filter, sort, detail open/close, no horizontal scroll, and the wide-screen table (set the viewport in the test).

Keep `explorer-count` and the other test ids the foundation e2e relies on (see `tests/e2e/helpers.js` and `tests/e2e/shell.spec.js`), or update those tests in the same commit.
