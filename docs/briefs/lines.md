## What to build

1. **Parse the line and the side** of every pick in the data layer (`src/data/normalize.js` plus a small pure module, e.g. `src/data/lines.js`): `line: number | null` (4.5, 9.5, 2.5, +0.25, −1…), the existing `side` extended as needed (over, under; for handicaps and result markets keep whatever is sensible and documented), `lineKey` (a stable string such as `under:4.5`, `over:9.5`, `ah:+0.25`) and a display label built with i18n ("Under 4.5", "Over 9.5", "Hándicap +0.25"). Cover match totals and team totals for goals, corners, cards and shots / shots on target, Asian handicap lines, and builders/doubles (no single line: null). To learn the real formats you may read, strictly read-only, only these ranges of the real sheet with `mcp__Google_Sheets__get_values` (load it with ToolSearch; spreadsheet ID `<SPREADSHEET_ID>`): `Sombra!D:E`, `Grok!E:F`, `Apuestas!F:G` (market and selection columns; never any other tab or column, never any other Google Sheets tool, and copy no real rows into the repo). Write unit tests with synthetic copies of every shape you find, and report how many real selections did not yield a line where you expected one.
2. **Filter state**: new fields `sides` (over / under) and `lines` (list of `lineKey`s) and `passedAll` (boolean: model picks that passed every filter; the Tests section needs it), with URL keys, `fromQuery` / `toQuery` round-trip, `applyFilters`, `facetCounts`, `activeEntries` (chips such as "Under 4.5"), all additive and unit-tested. Old URLs and saved presets keep working.
3. **Filter panel**: a "Línea" section (Spanish) / "Line" right after Tag and Market: side chips (Over, Under) and line chips with counts ("Under 4.5 · 23"), sorted by line, grouped by market family when the current picks span several (cards, corners, goals…). The section shows only lines that exist under the other active filters, and hides itself when no pick has a line. This must make "TARJETAS UNDER + Under 4.5" two taps. Add two or three built-in presets that use it (for example "Tarjetas Under 4.5").
4. **Show it**: the pick card and the detail sheet show the line label where they show the selection only if it adds information (do not duplicate text); the Explorer table gets no new column.
5. **Break down by line**: a grouping helper in `src/data/` (unit-tested) and a "Por línea" option in the Simulator's breakdown block (rows link to the Explorer with that line added). The Overview's tag table: under each tag row with at least two lines, an expandable "por línea" list (n, record, yield, EV vs close with n, verdict) would answer Juan's question at a glance; build it if it fits cleanly in `src/features/overview`, compact and collapsed by default.
6. **Tests section links**: `src/data/tests-config.js` holds an `explorer` filter object per test, approximate where the filters could not express the membership ("passed every filter", the under side, the Under 4.5 control line). Tighten them with the new fields, keep the "approximate" note only where it is still true, and unit-test that each test's Explorer link selects the same picks as the test's own membership function wherever that is now expressible.
7. **Fix**: a pick priced exactly 1.70 is counted in two slices: `priceBand(1.7)` (in `src/data/simulate.js` or `stats.js`) and the price presets disagree at the boundary, so a breakdown row's link can show a different n than the row. Make breakdown bands disjoint, make every breakdown row link select exactly the picks of that row (use an explicit min/max range in the link if presets cannot express it), and unit-test the boundaries (1.70, 2.00, 2.50, 4.00). The presets Juan asked for (≤2.0, <2.0, ≤2.5…) keep their meaning.

E2E: line filter alone and combined with a tag, chips and removal, URL round-trip through reload, the built-in preset, the Simulator "por línea" breakdown link landing on the same count in the Explorer, English, no horizontal scroll on phone and desktop. Update `docs/FEATURE_GUIDE.md` and `docs/DATA_CONTRACT.md` (the `Pick` fields) for what you add.
